# Popup primitive (issue [#96](https://github.com/WonderForgeLabs/gooey/issues/96))

**Status:** executed, landed in [PR #143](https://github.com/WonderForgeLabs/gooey/pull/143).

**Date:** 2026-08-10

## What was asked for

Wave 2 deliberately did NOT extract a popup primitive: "two overlays is
not enough evidence for the right abstraction"
([toolkit wave 2](2026-08-10-toolkit-wave2.md)). The evidence is now
n=4 — the MenuBar dropdown, the Tooltip popup, the demo browser's
source picker ([browser branches](2026-08-10-browser-branches.md)), and
the ToastHost hosting shape — each hand-rolling some mix of the same
mechanics:

- placement against an anchor rect (the tooltip's below/flip/clamp);
- open/close lifecycle, with the **collapsed-overlay subscription
  hazard**: a Collapsed surface's paint node never evaluates its
  Render, so it never subscribes to the open property, so the FIRST
  open schedules no frame — the browser picker hit this and worked
  around it with an app-side "hint computed" carrier;
- modal keys (an open overlay swallows what it does not understand);
- held pointer capture with click-outside-dismisses-and-is-consumed;
- focus save/restore under the wave-2 rules (mouse-open restores
  `PreviouslyFocused`, key-open restores nothing, restore only while
  the owner still holds focus);
- z-hosting as last-in-document-order, with `HitTestTransparent` for
  page-spanning hosts.

Extract that once, into `components/popup.go`, and adopt it: MenuBar
fully (all existing menu tests unchanged — they are the behavioral
contract), Tooltip for the pieces that fit.

## Plan

A `Popup` lifecycle object plus a primitive-owned surface leaf, with
the OWNER staying an ordinary component — not a "popup framework". The
owner keeps everything domain-shaped (what to show, where it goes,
which gestures mean what) and forwards three seams: the `FocusHost`
call, its `Arrange`, and its key/mouse fall-throughs. Placement is a
pure function (`PlacePopup`), separate from the lifecycle, because the
two are adopted independently — the tooltip needs placement without
modal focus, the menu needs the lifecycle with its own non-flipping
geometry.

## Executed

### API (`components/popup.go`)

```go
func NewPopup(owner gooey.Component, draw func(*gooey.Frame, gooey.Rect)) *Popup

type Popup struct{ Modal bool /* swallow unhandled keys while open */ }

func (p *Popup) Surface() gooey.Component            // the leaf; owner returns it LAST from ChildComponents
func (p *Popup) SurfaceBounds() gooey.Rect           // for the owner's hit math
func (p *Popup) SetFocusManager(*gooey.FocusManager) // owner forwards its FocusHost call
func (p *Popup) Manager() *gooey.FocusManager
func (p *Popup) IsOpen() bool                        // call site decides: paint dep or plain question
func (p *Popup) Open(restore gooey.Component)        // focus + HELD capture → owner
func (p *Popup) Dismiss()                            // idempotent; releases, restores
func (p *Popup) MouseOpenRestore() gooey.Component   // the wave-2 mouse-open rule
func (p *Popup) ArrangeSurface(show bool, r gooey.Rect) // from the owner's Arrange
func (p *Popup) HandleKey(ev input.KeyEvent) bool    // owner's key fall-through
func (p *Popup) HandleMouse(ev input.MouseEvent) bool // owner's pointer fall-through

func PlacePopup(anchor gooey.Rect, sz gooey.Size, bounds gooey.Rect, side PopupSide) gooey.Rect
```

The owner wiring is four lines: construct with a draw func, return
`Surface()` last from `ChildComponents`, call `ArrangeSurface` from
`Arrange`, and end the key/mouse handlers with the fall-throughs.

### The subscription hazard, solved once

The surface is **never Collapsed**: while closed it stays Visible and
is arranged to a **zero rect**. A Visible zero-size leaf's paint node
evaluates on the very first frame (Collapsed and Hidden nodes skip
Render; zero-size Visible does not), and the surface's Render reads the
open property BEFORE its bounds early-return — so the subscription
exists before the popup has ever opened, and the first `Open` dirties
the surface itself. No app-side carrier, no owner chrome that happens
to read the flag. Zero-size also means: not hit-testable, occupies
nothing, paints nothing, clears nothing.

Appear/vanish damage rides the Composer's **bounds sweep** rather than
the visibility sweep: opening is zero→rect (rev bump, first paint),
dismissing is rect→zero (the sweep clears the vacated cells and
`restoreUnder` repaints what they covered). Same counts as the old
Collapsed-flip on every pinned path.

Pinned by `TestPopupFirstOpenSchedulesItsOwnFrame`, whose page
deliberately has NO other reader of `IsOpen`: open schedules a frame
(OnInvalidate observed) and paints exactly 1 component (the surface).

### Dismissal grammar

`HandleKey` (owner's fall-through): esc dismisses and is consumed;
`Modal` swallows everything else the owner declined. `HandleMouse`: a
press the owner did not claim dismisses AND is consumed — the held
capture routed it here precisely so it never reaches, or activates,
what is underneath — and the release/click residue of that gesture is
swallowed. Both return false while closed, so owners call them
unconditionally.

### Focus rules (wave 2, now pinned at the primitive)

`Open(restore)`: focus and held capture go to the owner. Mouse opens
pass `MouseOpenRestore()` (focus-follows-click has already moved focus
to the owner; the component to give it back to is the one the manager
remembers losing). Key opens pass nil. Accelerator opens pass whatever
held focus when the accelerator fired (the menu does this itself —
focus has NOT moved yet on the mnemonic path). `Dismiss` restores only
while focus is still on the owner
(`TestPopupDismissAfterFocusMovedOnLeavesFocusAlone`).

### Adoption

**MenuBar — full.** `menuPopup` deleted; the dropdown is the
primitive's surface drawn by `MenuBar.drawDropdown` (selection and
CanExecute reads stay inside the surface's node, keeping navigate=1 and
condition-flip=1). Open/Dismiss/focus/capture/esc/modal-swallow/outside
-press all delegate; `pressRestore` became `MouseOpenRestore`. The bar
keeps: mnemonics and accelerator routing, gesture hints, item
semantics, its non-flipping `popupRect` geometry (a dropdown below the
bar CLIPS at the screen edge rather than flipping over the bar —
deliberate, so `PlacePopup` is not used here), title spans, hover
tracking. **Every existing menu test passes unchanged**, including the
damage pins (open=2, navigate=1, alt-open=3) and the live-dispatch
test — the tests are the behavioral contract for this refactor.

**Tooltip — placement only.** `tipPopup.Place` is now one `PlacePopup`
call (below, flip above, clamp — the function was generalized FROM
this code, verified by the unchanged tooltip suite, including
`TestTooltipFlipsAboveAtTheScreenEdge`). The lifecycle half does NOT
fit and stays on the AdornmentLayer: a tooltip takes no focus, holds no
capture, swallows nothing, and its show/hide is structural
(`Add`/`Remove` raise the structure hook, which schedules frames by
itself — the subscription hazard cannot exist on that path).

**Toasts — no adoption, by design.** A toast is not an anchored popup:
it has no anchor (host-corner stacking), no dismissal grammar (a timer,
not esc/click-away), no focus or capture semantics, and no modality.
What it shares with Popup is only the z-hosting convention
(last-in-document-order + `HitTestTransparent` host), which is a
convention, not code.

**Browser picker — follow-up, not adopted here.** It is popup-shaped
and would fit, but (a) it dismisses on outside CLICK where the
primitive standardizes on outside PRESS (the Windows-menu gesture wave
2 chose) — adoption changes a user-visible gesture and
`TestPickerClickOutsideDismissesWithoutActivating`; (b) its damage pins
and `picker.popup` field are asserted directly by `picker_test.go`, so
"tests unchanged" cannot hold; (c) it lives beside the source-switching
machinery this task was told not to disturb. Adopting it (and deleting
the now-redundant hint-carrier comment contract in `main.go`) is a
clean, separate change.

### Tests

New in `components/popup_test.go`, against a toy owner whose page has
no accidental subscription carrier: first-open-schedules-its-own-frame
(the hazard pin), esc dismiss + capture release + restore-beneath +
settle-0, mouse-open vs key-open focus restore, dismiss-after-focus-
moved-on, click-outside-dismisses-and-is-consumed, modal swallow (with
a page KeyBinding proving nothing leaks) and non-modal fall-through,
and a `PlacePopup` table (fits, flips both ways, clamps both axes,
oversized, no-room-either-side).

## Invariants touched

- **Damage discipline (invariant 3): preserved, mechanism shifted.**
  The menu dropdown's appear/vanish moved from the visibility sweep to
  the bounds sweep (Collapsed-flip → zero-rect). All pinned counts are
  unchanged; the menu tests are the proof. The zero-size closed surface
  evaluates once at composition start (every node does) and then only
  when the popup actually opens or closes.
- **Lazy property graph (invariant 2): the primitive encodes the
  call-site rule.** The surface's Render reads the open property before
  any early return (subscription); `ArrangeSurface` and the event
  helpers read it from layout/handlers (plain). This is the Get-order
  lesson (hoist Gets above early returns) built into a component so
  customers cannot get it wrong.
- **Input routing (invariant 6): no dispatch-order change.** The
  primitive uses the existing capture/FocusHost seams; modal swallowing
  happens inside the owner's own bubble slot, exactly where the menu's
  hand-rolled version sat.

## Not in this wave

A markup `<Popup>` element (Popup is a Go-side primitive; a markup
surface should arrive with a future markup-first customer — Flyout or
ComboBox); browser picker adoption (above); an outside-CLICK dismissal
policy knob (add when the picker adopts); placement sides beyond
below/above (left/right for flyouts); the issue's `docs/learn/` popup
chapter + example GIF and README status row (docs pass, alongside the
learn examples workflow); context menus at the pointer (same machinery,
a point anchor).
