# The exec pack: sys:Run behind an allowlist (executed)

Status: implemented 2026-08-10 (issue #158, Elan's stdlib expansion
3/4). Owner: `handlers/exec` — a nested module. Built under the pack
distribution doctrine (`2026-08-10-pack-distribution.md`); the
jq/deserialize tail is reconciled with the pipeline-grammar-v2 record
(`2026-08-10-pipeline-grammar-v2.md`) below.

Elan's sketch, verbatim:

> `={sys:exec $cmd,$args[],os-agnostic-stderr/out capture requests
> enum | jq $jqExpression | json:Deserialize }`

Read as intent: markup runs a command with arguments, says which
streams it wants in an OS-agnostic way, extracts structure with jq,
and lands typed data. Two of those four are v1-expressible today; two
are pipeline-grammar-v2 territory and are mapped onto it explicitly
rather than half-built here.

## The allowlist is the grant

The doctrine's sentence, applied at its sharpest: **untrusted markup
never names a binary.** Registration enumerates every command markup
may run — the allowlist is the grant, fixed at construction, and no
markup syntax can expand it:

```go
p, err := exechandlers.New([]exechandlers.Command{
        {Name: "git-status", Path: "git", Args: []string{"status", "--short"}},
        {Name: "list-pods", Path: "kubectl",
                Args: []string{"get", "pods", "-o", "json"},
                Jq:   ".items[].metadata.name"},
})
markup.RegisterHandlers(exechandlers.URI, p) // URI = "gooey.dev/handlers/exec"
```

```xml
<Gooey xmlns:sys="gooey.dev/handlers/exec">
  <Button Content="pods" Click="{{sys:Run `list-pods` | into .Pods}}"/>
```

The command name **must be a backtick literal** — a bound `.Path`
there is a load error by design, because a runtime value cannot be
checked against the allowlist at load time, and load time is where
this framework refuses things. An unregistered name is likewise a load
error naming the registered set. `sys:` is the conventional prefix;
as everywhere, the document picks its prefix and the URI is the
identity.

Three further clamps, all in the `Command` registration:

- **No shell, ever.** `Path` + baked `Args` + appended markup
  arguments form an argv; nothing is re-parsed by a shell. A host may
  itself register `/bin/sh -c "…"` as a fixed script — that is the
  host's prerogative and the test suite does it — but markup-supplied
  strings are only ever argv elements.
- **`ArgPolicy` gates markup arguments.** The default `ArgsNone`
  means the registered argv is the whole argv — markup passing any
  argument is a load error (argument *count* is static, so the check
  is load-time). `ArgsAny` opts a command into appended arguments,
  optionally capped by `MaxArgs`. Argument *values* are the
  document's — grant `ArgsAny` only to commands safe under arbitrary
  argv tails.
- **The environment is scrubbed by construction.** The child starts
  from an **empty** environment (`cmd.Env = []string{}`, non-nil —
  nil would mean inherit), plus `PassEnv` names copied from the host
  environment if set, plus explicit `Env` entries. Secrets in the
  app's environment do not exist for children unless named.

Bare `Path` names ("git") resolve through the PATH once, at `New`, and
pin to the absolute result — what runs later is what the host saw at
startup. Every registration defect (duplicate or unspellable name,
unresolvable path, non-compiling jq, `MaxArgs` under `ArgsNone`,
negative timeout, out-of-range capture) errors at `New`, i.e. app
startup.

## The v1 grammar: options as literals

v1's expression grammar (`markup/expr.go`) has exactly two argument
atoms — `.Path` and `` `literal` `` — and one stage, `into`. **No new
pipe stages are invented here**; the sketch's `| jq | json:Deserialize`
tail is precisely what pipeline-grammar-v2 reserves transform space
for, so v1 spells those provider-side, as *option literals*:

```
{{sys:Run `name` [`capture=MODE`] [`jq=EXPR`] [`--`] [args…] | into .Out}}
```

Options sit between the command name and the arguments, each at most
once. They are **literals by definition** — a bound `.Path` in option
position is simply the first argument — which keeps every option a
load-time fact: a bad capture mode or a non-compiling jq expression
fails the load. A `` `--` `` literal ends option scanning, so a
command whose first real argument starts with `capture=` or `jq=` can
still receive it (bake stranger cases into registration `Args`).

Bound arguments keep the house lvalue semantics: handles resolved at
load, values read at click time on the UI goroutine, then handed to
the process goroutine as strings.

## The capture enum

OS-agnostic by construction — streams and exit codes, no signals, no
shell redirection:

| mode | delivers | non-zero exit is |
|---|---|---|
| `stdout` (default) | standard output | `"ERROR: name: exit status N: first-stderr-line"` |
| `stderr` | standard error | error |
| `combined` | both streams through **one pipe**, in write order (the `2>&1` shape without a shell) | error |
| `both` | tagged JSON: `{"exit":N,"stdout":"…","stderr":"…"}` | **data** — the object always arrives |
| `exit-code` | the decimal exit code (`"0"`, `"1"`, …) | **data** |

Spelled `Capture` on the registration (the default) and `capture=…`
per call. The stream modes treat failure as failure because their
consumer bound one string for *output*; the structured modes exist
exactly so a page can treat exit status as data (`git diff --quiet`
callers, health checks). `both` is a struct-marshal, so key order is
deterministic; it is deliberately the JSON shape jq composes with
(`capture=both` + `jq=.stderr`).

Each stream is capped (`WithMaxOutput`, 1 MiB default) by a bounded
buffer that keeps draining past the cap — the child can never block on
a full pipe, and a runaway stream cannot become the app's memory
profile (net's `MaxBody` argument, process edition).

## jq today: provider-side, one engine

The dependency decision: **take gojq** (`github.com/itchyny/gojq`,
pure Go). The sketch's `| jq $jqExpression` makes structured
extraction the point of the pack, and provider-side `Jq` is its
v1-expressible form. Per the doctrine's module-boundary rule, any
third-party dependency forces a nested module: `handlers/exec` has its
own `go.mod` with `replace … => ../..`, the `handlers/temporal`
pattern, and its own CI step. The root graph provably excludes gojq.

Semantics, registration `Jq` or per-call `jq=` (the call overrides):

- compiled at registration/load respectively — a bad expression never
  reaches a click;
- applied to the *delivered text*, which must parse as JSON
  (`"ERROR: name: jq input is not JSON: …"` otherwise);
- string results deliver raw (the `jq -r` shape — what a Text binding
  wants); non-strings re-marshal as JSON; multiple results join with
  newlines, matching the jq CLI;
- a jq runtime error is an `"ERROR: name: jq: …"` delivery.

Delivery stays a string because the property boundary is strings in
v1 — the same protojson-at-the-edge posture as the temporal-visibility
pack: structured payloads cross as canonical JSON text, and consumers
project them (`components.ItemsOf` after an `encoding/json` parse in a
viewmodel computed) rather than receiving framework-typed objects.

## Process hygiene

Per the companions record (`2026-08-10-companions.md`), one level
down:

- **Own process group** (Unix, `Setpgid`) — killing the command kills
  what *it* started, and the child can never sit in the terminal's
  foreground group.
- **Never a tty.** Stdin is the null device; stdout/stderr are pipes
  into the bounded buffers or the null device. Nothing a child prints
  can paint over the raw-mode screen.
- **Timeout → escalation.** Per-command `Timeout` (else provider
  default 30s); on expiry SIGTERM to the group, `WithKillDelay` grace
  (2s default), SIGKILL to the group, and the goroutine **joins
  `Wait`** before delivering — no orphaned pipes, no leaked process
  accounting. Non-Unix signals the process alone (`exec_other.go`),
  the same honestly-different story as `companion_other.go`.
- Delivery is `Target.Deliver` — one Dispatcher post onto the UI
  goroutine — after argument snapshots were taken *on* the UI
  goroutine inside the Command. UI confinement unchanged.

## The v2 mapping (the sketch's tail, placed)

The pipeline-grammar-v2 record splits stages into **clauses** on one
call (`into err progress retry timeout`, order-free, at most once) and
**transforms** — ordered value stages, the #99 converter side, living
in the non-reserved stage-name space v2 explicitly keeps open. The
sketch's tail lands there as follows:

- **`| jq EXPR` becomes a transform stage.** `jq` is not a reserved
  clause name, so `{{sys:Run `list-pods` | jq `.items[].name` | into
  .Pods}}` is exactly the shape #99's converter stages will parse — an
  ordered transform over the delivered string, upstream of `into`.
  Same gojq engine, one implementation: the provider's option-literal
  spelling (`jq=…`) is the v1 bridge and stays for compatibility, but
  the stage form becomes canonical when #99 lands. Nothing to unlearn:
  compile-at-load, string-raw/JSON-remarshal, newline joining carry
  over as the stage's semantics.
- **The capture enum is v1's stand-in for multiple `into` targets.**
  Under v2 introspection `sys:Run` declares results
  `(stdout string, stderr string, exit int)`; `| into .Out .Err .Code`
  with prefix mapping replaces `capture=both` (and `exit-code`, by a
  page that names all three and reads the third). The tagged-JSON
  delivery then becomes a compatibility mode rather than the only
  structured form. `capture=stderr`/`combined` remain useful — prefix
  mapping is positional and cannot *skip* stdout, so stream selection
  stays a provider option even in v2.
- **`json:Deserialize` is typed targets plus projection.** v2 types
  `into` targets through the `propKinds` table (`exit` into a
  `*prop.Property[int]` directly); for structured payloads the
  delivered string stays canonical JSON at the property boundary, and
  the deserialize step is the consumer's projection — today a
  viewmodel computed over `components.ItemsOf`, later #99 converters
  or DataTemplates over the same text. A reflective
  deserialize-into-arbitrary-structs stage is exactly what the
  no-reflection rule excludes.
- **`| err .Err` supersedes the `"ERROR: …"` strings** for pages that
  declare it, per v2's err-tail rules (into unchanged on failure, err
  cleared on success); the string fallback here is v1-conformant and
  becomes v2's legacy path unchanged.
- **`retry`/`timeout` stages: one wrinkle worth recording.** Local
  commands are arbitrary and not idempotent by default, so exec should
  surface **zero retry caps unless a registration opts in** — under
  v2's rule, caps of zero make `| retry` a load error, which is the
  right default for `rm`-shaped registrations. But v2's `FnInfo` is
  keyed per *function*, and exec's budgets are per *Command* — one
  `Run` serves many registrations. When exec adopts v2, `Describe`
  needs the resolved call (function + literal first argument), not the
  function name alone; noted here so the v2 implementation grows that
  seam deliberately rather than discovering it.

## Tests

`handlers/exec/exec_test.go` + `exec_unix_test.go`, in net's
markup-harness style (fstest.MapFS page, hand-pumped Dispatcher). The
process fixture is `testdata/helper`, built by `TestMain` into a temp
dir — portable behavior, no committed binaries, no guessing at OS
tools. Coverage:

- allowlist: unregistered name, bound name, args under `ArgsNone`,
  `MaxArgs` — all load errors; registration defects all error at
  `New`;
- capture: all five modes, per-call override, non-zero exit as error
  (stream modes) vs data (`both`/`exit-code`);
- jq: registration and per-call, override precedence, multi-result
  joining, non-string re-marshaling, non-JSON input error,
  `both`+jq composition;
- environment: empty-by-default proven (a parent secret does not
  appear), `Env` injection, `PassEnv` pass-through, absent `PassEnv`
  names not invented;
- hygiene (unix-only file, like mcp's e2e precedent): a
  SIGTERM-ignoring child is SIGKILLed within the grace; a
  grandchild backgrounded by a registered `/bin/sh` script dies with
  the group (the companions discriminator, re-proven here);
- the damage contract: a delivery repaints exactly the bound Text;
- inventory: `AllNames()` pinned (`NameRun`), the unknown-function
  error derived from it.

## Explicitly out

- **Fire-and-forget** — `| into` is required (net's posture). A page
  that wants side effects without output can bind `.Out` to a sink
  property; loosening this is a one-line provider change if wanted.
- **stdin piping** into the child — a later `input=`-style option or
  v2 argument; today stdin is the null device, full stop.
- **Streaming/partial output** — v2 `| progress` territory; exec
  would declare the capability then.
- **PTY allocation** — never. A child that needs a terminal is an
  application, not a command; the terminal belongs to gooey
  (`2026-08-10-tty-read-lifecycle.md`).
- **Per-call env/dir/timeout** — the grant's scope is the
  registration's; widening at the call site would let markup negotiate
  its own sandbox.
- **Windows process-group parity** — signalled directly, documented
  as different, same as companions.
