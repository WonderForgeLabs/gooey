# fs handler pack (design)

Direction set by Elan 2026-08-10 (issue #157, stdlib expansion 2/4): an
`fs:` handler namespace whose registration grants a ROOT — the `fs.FS`
loading seam doubling as the security boundary — with reads by default
and writes only via an explicit read-write grant.

```xml
<Gooey xmlns="wonderforge.io/gooey/2026"
       xmlns:fs="gooey.dev/handlers/fs">
  <Button Content="open"  Click="{{fs:Read .Path | into .Content}}"/>
  <Button Content="files" Click="{{fs:List `docs` | into .Entries}}"/>
  <Button Content="save"  Click="{{fs:Write .Path .Draft | into .SaveStatus}}"/>
</Gooey>
```

```go
// Read-only: the fs.FS IS the grant's extent.
markup.RegisterHandlers(fshandlers.URI, fshandlers.New(os.DirFS("./docs")))

// Read-write: a separate, visible decision at the registration site.
p, err := fshandlers.NewWritable("./workspace")
markup.RegisterHandlers(fshandlers.URI, p)
```

## The grant is a root, not a permission bit

House doctrine says registration under a prefix is the capability
grant. For fs the grant carries an *extent*: `New(fsys fs.FS)` — an
`embed.FS` grants its embedded files, `os.DirFS` a subtree, a TarFS an
archive. The pack never decides what markup may touch, because the
value handed to the constructor already did.

Escapes are rejected structurally, per `fs.ValidPath`: paths are
relative, slash-separated, no `..`, no leading `/`, no `.` elements.
The check runs twice with the same text: a **literal** path argument is
validated at build time (a page shipping `` `../etc/passwd` `` fails to
load), and a **bound** argument is validated at invoke time, delivering
the ERROR into the target like any other runtime failure. Below the
path grammar, the read-only side inherits whatever containment the
granted `fs.FS` has, and the writable side gets OS-level enforcement
from `os.Root` — a symlink inside the root that points outside it
refuses to resolve (regression-tested).

**Read-only is the default posture.** There is no `WithWrites()`
option; the writable provider is a different constructor
(`NewWritable(dir string)`, `os.OpenRoot` under it — go.mod is at Go
1.25, so `Root.WriteFile`/`Root.OpenFile` are available). On a
read-only registration, `Write`/`Append` are *load* errors naming the
missing writable grant, not runtime surprises.

## Functions (v1 grammar)

All six live inside `{{fs:Fn args | into .Target}}` — one-shot,
command-shaped, target required, result a string. Arguments are the
DSL's atoms (backtick literals and `.Path` handles, read at invoke
time on the UI goroutine; the I/O runs on a worker goroutine and
delivers through the Dispatcher, exactly net's shape).

| Function | Args | Delivers |
|---|---|---|
| `Read` | path | file contents (capped) |
| `List` | dir | JSON array of entries |
| `Stat` | path | JSON of one entry |
| `Glob` | pattern | JSON array of matching paths (`[]`, never `null`) |
| `Write` | path, content | status: `""` on success (writable grant only) |
| `Append` | path, content | status: `""` on success (writable grant only) |

The entry shape is protojson-adjacent:

```json
{"name":"spec.md","size":1204,"dir":false,"modTime":"2026-08-10T12:00:00Z"}
```

`modTime` is RFC 3339 (protojson's Timestamp rendering); a zero mod
time renders as `""`, the way protojson leaves unset fields out.
`size` stays a JSON number — these are display values headed for a
terminal, not wire int64s, so protojson's int64-as-string rule is
deliberately not imported.

### The Read cap

`DefaultMaxRead = 1 MiB`, raised per provider with `WithMaxRead(n)`. A
markup pipeline pointed at a 2 GB log must not become the app's memory
profile. Over-cap files **fail** (ERROR naming the cap) rather than
truncate: a silently cut file is corrupt data, and unlike net's
response stream the file is all there — the caller should raise the
cap on purpose. Enforcement reads one byte past the cap through a
LimitReader: no Stat round-trip, no time-of-check gap, works on FSes
that report no size.

### Write/Append status semantics

v1 has no `| err` tail, and a write's only error channel is its
target. So the target is required and behaves as a **status slot**:
Set to `""` on success, the `ERROR: …` string on failure — the same
cleared-on-success semantics the pipeline-grammar-v2 record assigns to
`err` tails, so pages written today read naturally when the tail
arrives. Errors follow the house convention: load errors are typed
prose (`Write needs a status target — add `\| into .SomeProperty``),
runtime failures are `ERROR: fs:Write path: reason` strings.

## Watch: deferred, deliberately

A v1 handler is one-shot and command-shaped; watching a file is a
subscription with a lifetime. A `Watch` Command would leak a
watcher-goroutine per click with nothing to cancel it. File watching
belongs to the v2 stage grammar (where a call gains an owner able to
carry cancellation) or to a companion (which has Start/Stop bracketing
already). Noted for that design; not faked here.

## Packaging

Zero third-party dependencies ⇒ the pack lives in the ROOT module as
`handlers/fs` (package `fshandlers`), like `handlers/net` — the
separate-module quarantine exists for dependency graphs (Temporal's
SDK), not for stdlib-only packs. The binding rules are the
pack-distribution doctrine's
(`docs/specs/2026-08-10-pack-distribution.md`); this spec covers only
the fs pack. Per that record the pack also carries its contract
surface: `handlers/fs/README.md` (the pack contract doc), `Name*`
constants enumerated by `AllNames()`, and unknown-function error text
derived from those same lists — a read-only provider's error names
only the four functions its grant resolves.

## Executed (2026-08-10)

Landed exactly as designed: `handlers/fs/fs.go` (provider, both
constructors, six functions, cap, `Close` for the writable root's fd)
and `handlers/fs/fs_test.go` — table tests over `fstest.MapFS` and a
writable `t.TempDir()`, all through `markup.Load` in net's harness
style. Coverage: delivery into the target, the 1-repaint damage
assertion on the bound Text, invoke-time argument reads, every escape
shape (traversal, absolute, `./`, empty, trailing slash) at both parse
tiers, the symlink escape against `os.Root`, the size cap at and past
the boundary, JSON shapes for List/Stat/Glob (including `[]` for no
matches and `""` for zero mod times), Write/Append round-trips on
disk, the full load-error table (unknown function, arity, missing
target, bad literal pattern, writes on a read-only grant), and the
`AllNames()` inventory pin.

`docs/markup-reference.md` § Handler namespaces gained the fs rows and
the grant-is-a-root paragraph. No new demo binary (per the issue); the
registration example above is the demo surface.
